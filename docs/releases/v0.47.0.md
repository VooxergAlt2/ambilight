# Ambilight ESP32-C6 v0.47.0

v0.47.0 adds local-lighting presets, AUTO fallback from DDP to local lighting,
independent DDP/local brightness, and guarded browser OTA for normal
`firmware.bin` updates.

## Highlights

- `Ambilight` is now AUTO ownership: fresh DDP owns output; after 1.5 s without a complete frame, the configured local fallback takes over; fresh DDP automatically returns ownership.
- Independent persistent brightness banks for DDP and local lighting.
- Existing `output_state` schema 1 migrates by copying the old brightness into both banks.
- Local-lighting state is persisted separately: selected mode, fallback effect, RGB, speed and intensity.
- Effects: Ambilight, Solid, Rainbow, Breathing, Warm White, Bias White, Sunset, Candle, Aurora and Twinkle.
- Home Assistant/WLED compatibility exposes all 10 effects and predicts the correct brightness bank when an effect-only command changes owner.
- Web UI exposes both brightness banks, explicit AUTO fallback selection, color/speed/intensity controls and actual owner/fallback status.
- Backup format v2 includes both brightness banks and local-lighting state; v1 backups remain accepted.

## Wi-Fi OTA

System → Wi-Fi firmware update can arm OTA for 120 seconds. The controller creates a random one-time token; the browser then streams `firmware.bin` to HTTP/3232.

Before application flash writing starts, firmware validates ESP image magic, ESP32-C6 chip ID, first-segment size and `esp_app_desc_t` magic. The generated `firmware.factory.bin` and `bootloader.bin` fail this application-image check.

During an authorized upload the LEDs are blacked out and DDP rendering pauses. Failed uploads restore normal owner/brightness. Successful uploads remain black until reboot into the new slot. NVS is outside the app slots and is preserved.

The OTA endpoint is designed for a trusted LAN. It is not an authenticated/TLS Internet update service.

# Ambilight ESP32-C6 v0.47.0 — по-русски

В v0.47.0 добавлены локальные пресеты, автоматический fallback при пропадании DDP, раздельная яркость DDP/локальной подсветки и обновление `firmware.bin` по Wi-Fi.

## Основное

- `Ambilight` теперь AUTO: пока полный DDP-кадр свежий, выводом владеет DDP; через 1,5 с без полного кадра включается выбранный локальный fallback; свежий DDP автоматически возвращает Ambilight.
- Яркость DDP и локальной подсветки хранится раздельно.
- Старый `output_state` schema 1 мигрирует без визуального скачка: прежняя яркость копируется в оба банка.
- Локальный режим, fallback, RGB, speed и intensity сохраняются в NVS.
- Добавлены Warm White, Bias White, Sunset, Candle, Aurora и Twinkle к прежним Solid/Rainbow/Breathing.
- Web UI показывает фактического владельца вывода и позволяет отдельно выбрать AUTO fallback и обе яркости.
- Backup v2 сохраняет новые настройки, при этом backup v1 всё ещё восстанавливается.

## OTA по Wi-Fi

В System можно разрешить OTA на 120 секунд. Плата выдаёт одноразовый случайный токен, после чего браузер потоково отправляет `firmware.bin` на HTTP/3232.

До записи app-slot проверяются заголовок ESP image, chip ID ESP32-C6, размер первого сегмента и magic `esp_app_desc_t`. Поэтому `firmware.factory.bin` и `bootloader.bin` не принимаются как OTA-приложение.

На время записи LED гаснут, DDP-rendering приостанавливается. При ошибке прежний owner/brightness восстанавливается; при успехе контроллер остаётся погашенным до перезагрузки в новый slot. NVS сохраняется.

OTA рассчитан на доверенную LAN, а не на публикацию в Интернет.
