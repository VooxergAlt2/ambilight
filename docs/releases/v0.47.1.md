# Ambilight ESP32-C6 v0.47.1

v0.47.1 fixes the physical disabled/service-LED model and completes the
one-segment WLED-compatible Home Assistant control path.

## Highlights

- A configured disabled/service LED is now a real **physical wire-address hole**, not a logical pixel painted black.
- A side with `N` logical LEDs and one hole transmits `N+1` physical WS2812 addresses while keeping the DDP/ToF logical count at `N`.
- Logical pixels are remapped around the hole for both FWD and REV sides; no logical RGB pixel is discarded.
- The hole remains forced black in `LedEngine::show()` immediately before PARLIO encoding, so DDP, ACTIVE correction, local effects, logical commissioning and raw-GPIO commissioning cannot re-light it.
- Existing schema-2 mask offsets are preserved. The persisted binary format did not change, so an upgrade does not erase an already configured physical offset.
- Mask changes now resize PARLIO capacity transactionally under a safety blackout and roll back live geometry if durable persistence fails.
- Home Assistant segment 0 can now control power, brightness, RGB color, effect/mode, speed and intensity through the WLED-compatible JSON API.
- Master and segment-0 power/brightness describe the same output; when both are present, the more-specific segment fields win.
- Brightness is applied to the bank selected by the **resolved new effect**: Ambilight/AUTO uses the DDP bank, local effects use the local-lighting bank.
- Selecting RGB without an explicit effect enters Solid. Selecting `Ambilight` returns output ownership to AUTO while DDP reception continues in the background.
- The existing Web UI color picker, effect controls, speed/intensity controls and backup-v2 lighting state were re-verified against the same persistent lighting model.
- A rare topology post-commit failure can no longer be acknowledged as success: the output remains black and the caller receives failure/reboot-required semantics.

## Physical-hole contract

For a logical side of length `N`:

```text
physicalLength = N + 1
wireOrdinal = reversed ? N - 1 - logicalOffset : logicalOffset
physicalIndex = wireOrdinal >= hole ? wireOrdinal + 1 : wireOrdinal
```

The stored hole number is always a zero-based **physical** offset measured from
DATA input and therefore does not change when FWD/REV changes. Web UI presents
the same value as a human-friendly one-based physical LED number.

Valid zero-based offsets are `0..N` inclusive. A logical side length of 65,535
cannot also contain a hole because the resulting 65,536-address physical lane
would exceed the current uint16 driver/write-view representation.

## Home Assistant surface

The WLED-compatible facade exposes one full-length RGB segment. Its state/write
contract now includes:

```text
seg[0].on   power
seg[0].bri  brightness
seg[0].col  RGB color
seg[0].fx   Ambilight/AUTO or local effect
seg[0].sx   effect speed
seg[0].ix   effect intensity
```

Effect IDs remain stable:

```text
0 Ambilight (AUTO)
1 Solid
2 Rainbow
3 Breathing
4 Warm White
5 Bias White
6 Sunset
7 Candle
8 Aurora
9 Twinkle
```

The firmware still does not implement the full WLED renderer, arbitrary
segments, presets/playlists, WLED realtime UDP, Hyperk control or WLED firmware
OTA. HyperHDR realtime video remains DDP UDP/4048.

# Ambilight ESP32-C6 v0.47.1 — по-русски

v0.47.1 исправляет физическую маску служебного LED и завершает управление
контроллером из Home Assistant через односегментный WLED-compatible API.

## Основное

- Отключённый/служебный LED теперь является настоящей **дыркой в физическом адресном пространстве линии**, а не логическим пикселем, которому просто присваивается чёрный цвет.
- Для стороны с `N` логическими LED и одной дыркой в провод уходит `N+1` физических WS2812-адресов, но DDP/ToF по-прежнему работают с `N` логическими пикселями.
- Логические пиксели обходят физическую дырку и в FWD, и в REV, поэтому ни один RGB-пиксель не теряется.
- Непосредственно перед PARLIO encode служебный адрес дополнительно принудительно обнуляется в `LedEngine::show()`. Его не могут зажечь DDP, ACTIVE-коррекция, локальные эффекты или режимы пусконаладки.
- Существующие schema-2 offsets маски сохраняются. Формат NVS не менялся, поэтому после обновления уже заданный физический номер начинает работать с исправленной семантикой без сброса настройки.
- Изменение маски выполняется через защитное гашение, при необходимости меняет длину PARLIO и откатывает live-геометрию при ошибке сохранения.
- Home Assistant теперь может через segment 0 управлять питанием, яркостью, RGB-цветом, режимом/эффектом, speed и intensity.
- Master и segment 0 управляют одним физическим выходом; если в одном запросе есть оба значения, segment 0 имеет приоритет.
- Яркость записывается в банк уже **нового выбранного режима**: Ambilight/AUTO использует DDP brightness, локальный эффект использует lighting brightness.
- Выбор RGB без явного эффекта переводит подсветку в Solid. Выбор `Ambilight` возвращает AUTO, а DDP всё это время продолжает приниматься в фоне.
- Цветовой picker и остальные элементы управления в Web UI проверены на том же persistent lighting state.
- Редкий отказ после commit топологии больше не маскируется успешным ответом: вывод остаётся погашенным, а вызывающая сторона получает ошибку с требованием перезагрузки.

## Контракт физической дырки

Для логической стороны длиной `N`:

```text
physicalLength = N + 1
wireOrdinal = reversed ? N - 1 - logicalOffset : logicalOffset
physicalIndex = wireOrdinal >= hole ? wireOrdinal + 1 : wireOrdinal
```

Offset всегда физический, нулевой и считается от DATA-входа. REV/FWD его не
переопределяет. В Web UI номер показывается человеку с единицы.

Допустимы offsets `0..N` включительно. При логической длине 65 535 служебный
LED недоступен, потому что физическая линия потребовала бы 65 536 адресов, что
выходит за текущий uint16-контракт драйвера.

## Home Assistant

Односегментный WLED-compatible интерфейс поддерживает:

```text
seg[0].on   питание
seg[0].bri  яркость
seg[0].col  RGB-цвет
seg[0].fx   Ambilight/AUTO или локальный эффект
seg[0].sx   скорость эффекта
seg[0].ix   интенсивность эффекта
```

ID эффектов: 0 Ambilight, 1 Solid, 2 Rainbow, 3 Breathing, 4 Warm White,
5 Bias White, 6 Sunset, 7 Candle, 8 Aurora, 9 Twinkle.

Полный движок WLED, произвольные сегменты, presets/playlists, WLED realtime UDP,
Hyperk и WLED OTA намеренно не реализованы. HyperHDR по-прежнему должен слать
realtime-видео обычным DDP на UDP/4048.
